# 婚約訂單管理系統 V6 統一資料庫版

## 啟動

1. 將 ZIP 完整解壓縮到 ERP 電腦本機資料夾。
2. 雙擊 `START_WEDDING_ORDERS_WEB.bat`。
3. 瀏覽器會開啟 `http://127.0.0.1:8765/`。
4. 關閉標題為「婚約訂單網站」的黑色視窗即可停止網站。

網站執行期間黑色視窗會保持開啟，請不要關閉。啟動器會先檢查內附 Python、網站程式、正式資料庫及 8765 連接埠，等 `/api/health` 回傳正常後才開啟瀏覽器。啟動失敗時視窗會保留，錯誤寫入 `logs/web_startup_error.log`；需要完整診斷時使用 `START_WEDDING_ORDERS_WEB_DEBUG.bat`。

網站不連網，SQLite 由內附 Python 直接讀取，不需要另外安裝 SQLite。網站、人工修正、每日 7 天掃描與最近 6 個月掃描全部共用唯一正式資料庫 `data/orders.db`。一般訂單查詢保持唯讀，只有受控寫入流程能修改資料。

## 功能

- 正式 SR 訂單清單與分頁。
- 訂單編號、品號與 MENUITEM 品名搜尋。
- 客戶搜尋欄位已預留；R6 歷史來源未提供客戶名稱，因此目前不猜測補值。
- 日期、月份、訂單分類篩選。
- 訂單完整多品項明細。
- 待確認清單、受保護原圖與人工修正表單。
- 人工修正支援多筆品項的增加、刪除與修改。
- 可選擇「確認並寫入正式訂單」、「標記不納入」或「暫時保留待確認」。
- 新訂單會建立訂單、版本與明細；既有訂單只有完整內容變更時才新增版本。
- 人工處理會保存原始值、新值、備註、操作時間及操作來源。
- 月份與分類統計。
- 21 筆月份第一筆缺口紀錄，僅記錄、不重掃。

## 圖片保留 7 天

第一次部署後，以目前 Windows 使用者雙擊 `INSTALL_7_DAY_IMAGE_CLEANUP.bat`。系統會建立每日 20:30 執行的排程：

- 只有 SQLite 判定為成功且超過 7 天的圖片可刪除。
- pending、受保護、資料不完整或路徑超出專案資料夾的圖片不刪。
- 待確認處理成功或標記不納入後，原圖仍至少保留 7 天。
- 每次清理寫入 `image_cleanup_runs` 與 `audit_logs`。
- 同一時間只執行一個清理工作。

目前 R6 回傳包的 19,841 張成功圖片已在完整備份後刪除；尚未處理的待確認資料各保留一張網站原圖。

## 待確認人工處理

1. 在網站上方選擇「待確認」。
2. 找到資料後按「人工處理」，核對左側原圖及右側欄位。
3. 門市固定為 `SR`；部門代號仍保存 ERP 原始值，正式納入的訂單必須為 `4001`。
4. 品項可使用「新增品項」或每列右側刪除按鈕調整。
5. 按「確認並寫入正式訂單」前，程式會驗證訂單編號、日期、品項、數量與金額。
6. 每次確認、排除或暫存前都會先備份資料庫；失敗時整筆 rollback。
7. 寫入成功後，正式訂單數與待確認數會立即更新。

同一張訂單已存在時，程式會比較主檔及全部品項。完全相同不會重複建立版本；內容不同才建立新版本並保留舊版本。

## 備份與還原

- 雙擊根目錄的 `BACKUP_FORMAL_DATABASE.bat`：使用 SQLite backup API 建立 `backups/formal/orders_YYYYMMDD_HHMMSS.db`，並驗證 quick_check 與外鍵。
- 人工處理前的自動備份位於 `backups/manual_review/`。
- 還原前先關閉網站與掃描工具，再雙擊根目錄的 `RESTORE_FORMAL_DATABASE.bat` 並輸入備份 `.db` 完整路徑。
- R6 完整原始備份位於開發專案 `backups/R6_RETURN_20260824_IMMUTABLE`，不可當作日常網站資料夾使用。
